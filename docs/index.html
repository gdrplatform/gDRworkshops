What is gDR?

gDR is an open-source R platform for end-to-end dose-response analysis of drug perturbation experiments. It standardizes how raw plate-reader data is imported, normalized, modeled, and visualized.

gDRimport gDRcore gDRutils gDRplots gDRviz

Standardized data

Bioconductor MultiAssayExperiment & SummarizedExperiment objects as the backbone

Two normalizations

Relative Viability (RV) and Growth Rate (GR) — both reported for every experiment

Reproducibility

Fully scriptable pipeline from raw Excel / CSV to publication-ready figures and tables

Shared Analysis Pipeline

Every example follows the same three-step workflow:

Step 1 Data Import
  • Read Excel / CSV plate files
  • Attach cell line & drug annotations
  • Raw-plate QC heatmaps
→
Step 2 Processing & QC
  • Normalize to RV & GR
  • Average replicates
  • Fit 4-parameter Hill curve
→
Step 3 Analysis
  • Metrics & curve export
  • Dose-response & heatmap plots
  • Synergy / biomarker analysis
Output: standardized Excel tables + publication-ready SVG/PNG figures, organized per assay type (averaged · metrics · excess · scores)

Small Drug Combination Screen

Example 1 — Study Design

ER+ Breast Cancer 4 Cell Lines 2 Drug Combinations

Cell lines

  • CAMA-1
  • EFM-19
  • MCF-7
  • T-47D

Drug combinations

  • Inavolisib (PIK3CA inhibitor)
     × Giredestrant (ESR1 antagonist)
  • Everolimus (MTOR inhibitor)
     × Giredestrant (ESR1 antagonist)

Scientific question

Do PI3K-pathway and estrogen-receptor inhibitors synergize in ER+ breast cancer cell lines?

Example 1 — What It Demonstrates

  • Reading Excel-based plate data (manifest + treatment + raw measurements)
  • Mapping controls to treatments and flagging QC outliers
  • Computing RV and GR dose-response curves for each drug alone and in combination
  • Calculating Bliss and HSA excess synergy scores at each dose matrix point
  • Generating per-cell-line synergy heatmaps and isobologram plots
  • Exporting a fully annotated Excel workbook of metrics and synergy scores
Ideal entry point — small dataset, focused biology, complete pipeline in <300 MB of raw files

# ── Libraries ────────────────────────────────────────────
library(gDRimport)   # data ingestion from plate-reader files
library(gDRcore)     # core pipeline functions
library(gDRutils)    # annotation helpers
library(gDR)         # meta-package (loads the full ecosystem)
library(gDRplots)    # visualization

# ── Point to raw files ────────────────────────────────────
manifest  <- "raw_data/9545combo_Manifest.xlsx"
treatment <- c("raw_data/0077_9545 combo_Treatment.xlsx",
               "raw_data/Evero_9545 combo_Treatment.xlsx", ...)
raw_data  <- c("raw_data/9545combo_rawdata.xlsx",
               "raw_data/Day0.rawdata.xlsx")

# ── Load annotations ─────────────────────────────────────
drug_annotation     <- fread("data_annotation/drug_annotation.csv")
cell_line_annotation <- fread("data_annotation/cell_line_annotation.csv")

# ── Single call merges manifest + treatment + plate reads ─
data_imported <- import_data(
  manifest, treatment, raw_data,
  instrument           = detect_file_format(raw_data[1]),
  cell_line_annotation = cell_line_annotation,
  drug_annotation      = drug_annotation
)
import_data() auto-detects the plate-reader format and merges the three file types into a single annotated data.table, ready for processing.

            path   = file.path(wd, "plots",
                               paste0("plate_stack_", barcode_name)),
            format = "png")
})
  • Red border — control signal below plate average (edge effect / pipetting error)
  • Orange border — treated signal above ceiling (precipitation / contamination)
  • Numbers inside wells = dose rank (1 = lowest, N = highest); expect signal to fall as rank rises

Code · Step 2 — Identify Experiment Types & Build SummarizedExperiments

2-processing_and_QC.Rmd · lines 249 – 310 ↗ View on GitHub 
# ── Load the data saved at the end of Step 1 ─────────────
data_imported <- qs_read(file.path(wd, "gDR_data", "gDR_input.qs2"))

# ── Auto-classify each row as single-agent or combination ─
dt_     <- identify_data_type(data_imported)
dt_list <- split_raw_data(dt_)
# → names(dt_list) prints: "single-agent"  "combination"

# ── Extract each type ─────────────────────────────────────
sa_name    <- get_supported_experiments("sa")    # "single-agent"
combo_name <- get_supported_experiments("combo") # "combination"

dt_sa    <- dt_list[[sa_name]]
dt_combo <- dt_list[[combo_name]]

# ── Structure into SummarizedExperiment (Bioconductor) ───
# Maps control (DMSO) wells to drug-treated wells
se_sa    <- create_SE(dt_sa,    data_type = sa_name)
se_combo <- create_SE(dt_combo, data_type = combo_name)
create_SE() stores raw treated values and mapped controls in separate assay slots (RawTreated / Controls). The control mapping QC heatmap flags missing DMSO wells in red.

Code · Step 2 — Normalize, Average & Fit Curves

2-processing_and_QC.Rmd · lines 406 – 838 ↗ View on GitHub 
# ── 1. Normalize: raw signal → RV (0–1) and GR (−1 to 1) ─
se_sa    <- normalize_SE(se_sa,    data_type = sa_name)
se_combo <- normalize_SE(se_combo, data_type = combo_name)
# Adds "Normalized" assay slot to each SE

# ── 2. Average technical replicates ───────────────────────
se_sa    <- average_SE(se_sa,    data_type = sa_name)
se_combo <- average_SE(se_combo, data_type = combo_name)
# Adds "Averaged" assay slot (mean + std per condition)

# ── 3. Fit dose-response models ───────────────────────────
# Single-agent: 4-parameter Hill → IC50, GR50, Emax, h, R²
se_sa    <- fit_SE(se_sa,                 data_type = sa_name)

# Combination: per-drug metrics + synergy assays
#   excess (Bliss/HSA at every dose point)
#   isobolograms · scores (summary CI, Bliss, HSA)
se_combo <- fit_SE.combinations(se_combo, data_type = combo_name)
Each function appends a new assay slot — the SE grows through the pipeline while always keeping all intermediate layers accessible.

Code · Step 2 — Assemble the MultiAssayExperiment

# ── Bundle both SummarizedExperiments into one MAE object ─
mae <- MultiAssayExperiment(
  experiments = setNames(
    list(se_sa, se_combo),
    c(sa_name, combo_name)   # "single-agent", "combination"
  )

# ── Apply gDR standard metadata conventions ───────────────
mae <- standardize_mae(mae)

# ── Save to disk (compressed, fast I/O) ───────────────────
qs_save(mae, file.path(wd, "gDR_data", "gDR_mae.qs2"))
  • The gDR_mae.qs2 file is the single hand-off between Step 2 and Step 3
  • The MAE holds all layers: raw → normalized → averaged → metrics → excess → scores
  • Alternative shortcut: runDrugResponseProcessingPipeline() executes steps 1–5 in one call

# ── Load the MAE and extract assay data ──────────────────
mae <- qs_read(file.path(wd, "gDR_data", "gDR_mae.qs2"))

assay_list <- MAEpply(mae, function(x) {
  lapply(setdiff(assayNames(x), c("RawTreated","Controls","Normalized")),
         function(y) convert_se_assay_to_dt(x, y,
                       unify_metadata = TRUE,
                       merge_additional_variables = TRUE))
})

response_metrics_excess      <- assay_list[["combination"]][["excess"]]
response_metrics_isobolograms <- assay_list[["combination"]][["isobolograms"]]

# ── Generate 2×2 synergy panel per cell line × drug pair ─
# Top-left: smoothed response · Top-right: CI plot
# Bottom: Bliss excess heatmap · HSA excess heatmap + isobologram
ls_plt_RV <- pmap(tab_grid,
  heatmap_combo_metrics_panel,
  dt_excess          = response_metrics_excess,
  dt_isobolograms    = response_metrics_isobolograms,
  iso_levels         = "0.5",           # draw IC50 isobologram line
  normalization_type = "RV")
Solid isobole line bowing inward = synergy (less drug needed). Warm colors in Bliss/HSA panels = combination benefit.

Can RAF/MEK inhibitor combinations overcome resistance in MAPK-driven skin cancers, and does response vary across a large cell-line panel?

Example 2 — What It Demonstrates

  • Ingesting 43 individual CSV plate files — one per cell line — alongside a manifest and template
  • Scaling the gDR pipeline to a large cell-line panel without changing the workflow
  • Plate-by-plate QC validation and control mapping across dozens of experiments
  • Population-level metric heatmaps revealing differential sensitivity across cell lines
  • Synergy scoring (Bliss + HSA) for both drug pairs across all 43 lines
  • Hierarchical clustering of response metrics to identify cell-line subgroups
Key lesson: the same three-step pipeline scales seamlessly from 4 to 43 cell lines with no code changes

Example 3 — Biomarker Discovery (Step 3-1)

This example adds a unique fourth step that integrates gDR metrics with external DepMap omics data:

Dose-Response Metrics IC50, GR50, AOC per cell line
×

→

  • Demonstrates how gDR connects phenotypic screening to molecular biomarker discovery

Optional Exercise

Sensitive vs. Resistant — Find the Extremes

Exercise — Sensitive vs. Resistant Cell Lines

Using the pre-computed MAE object (gDR_data/gDR_mae.qs2), answer: which cell lines respond most and least to treatment?

Steps

  • 1. Load — qs_read("gDR_data/gDR_mae.qs2")
  • 2. Extract — convert_se_assay_to_dt(mae[["single-agent"]], "Metrics")
  • 3. Filter — keep one drug, normalization_type == "RV"
  • 4. Rank — sort cell lines by x_AOC (area over curve)
  • 5. Select — top 3 most sensitive & bottom 3 most resistant
  • 6. Plot — overlay their dose-response curves, colored by group

What to expect

Zhou — subtle spread within ER+ breast; subtype may explain differences

Goetz — BRAF-mutant lines likely cluster in the sensitive tail for Vemurafenib

Hagenbeek — mesothelioma & uveal melanoma (YAP-driven) enriched among top responders to GDC-8025

The same 6-line code skeleton runs on all three examples — only the drug name changes.
